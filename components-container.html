Use `Container` when you want the standard centered docs or app-shell width without repeating `mx-auto w-full max-w-7xl px-4 md:px-6 lg:px-8`.

Default container

Centered content with shared width and padding defaults.

The built-in layout is ideal for docs pages, settings screens, and general content surfaces.

Your custom `Class` value is appended after the default container classes, so width or padding overrides can intentionally win when needed.

Narrower container

This example trims the reading width for dense prose or form-heavy screens.

  • The default centering still applies.
  • `max-w-4xl` overrides the wider default.
  • The component still keeps your content full width inside that cap.

Even tighter layout

Useful for narrow content flows like auth, onboarding, or confirmation states.

Card-like section

`Container` handles the outer layout, while your utility classes shape the visual surface. This is a common pattern for docs callouts, settings groups, and marketing sections.

  • Rounded corners and borders create the surface.
  • Extra `px-6 py-8` can override the default gutter when desired.
  • The centered width behavior still comes from `Container` itself.

Inherited element API

`Container` still inherits the shared `Element` surface.

  • Id: adds a standard HTML id.
  • Class / Style: lets you layer custom utilities or inline styles.
  • Margin / Padding: works alongside the default container layout.
  • Events: click, focus, and keyboard handlers are still available.
